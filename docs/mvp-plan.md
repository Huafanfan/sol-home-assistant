# 单房间 MVP 路线图

## 实施前门槛

本路线图列出的每一项“实现”工作，在修改代码、部署配置或数据模型前，必须先建立并接受对应的功能规格。规格使用 [`templates/feature-spec.md`](templates/feature-spec.md) 创建为 `docs/features/<feature>.md`，并按 [ADR-0004](decisions/ADR-0004-documentation-driven-development.md) 和 [`../AGENTS.md`](../AGENTS.md) 的规则回填验收证据。

涉及供应商、成本、隐私、权限、部署或不可逆副作用的工作还必须先有 ADR；不得只因为路线图列出了一个方向，就跳过设计和确认门槛。

## 0. 先写清楚可验收的产品边界

- 首版用户：一个已授权的家庭成员。
- 首版环境：当前持续运行的 Mac mini 作为中心与第一台开发卫星。
- 首版目标：本地唤醒后可连续说话、可打断、可查看和删除历史记录。

首版语音闭环固定为“本地唤醒/VAD → 腾讯云 ASR → Gateway 路由 → 文本推理适配器（仅在需要时）→ 腾讯云 TTS”。不要求官方 OpenAI API 密钥，也不假定文本代理支持音频或联网搜索。

首版不承诺多人声纹识别、跨房间无缝转移、智能家居写操作、联网搜索或“任何话都永久记住”。

## 1. Mac mini 与 OrbStack 部署基线

实现：

- macOS 宿主机负责第一台 Voice Satellite 的麦克风、扬声器、唤醒、VAD、静音和状态提示；不把实时音频硬件路径塞入 Docker；
- OrbStack 提供 Docker Engine 与 Docker Compose；Gateway、Memory 和未来基础服务按容器服务边界设计；
- Dockerfile 与 compose.yaml 以 linux/arm64 为当前运行目标，并避免阻碍将来发布 linux/amd64 镜像；
- 会话、记忆和数据库数据使用持久化卷或 SOL_DATA_DIR；容器重建不能清空用户数据；
- 不开放 Docker TCP API，不向 Sol 容器挂载 Docker Socket，不使用 host network 作为跨设备通信方案；
- 在有 compose 服务前不创建空壳常驻容器；配置文件与真实凭据仍留在未提交的本机环境。

验收：

- 当前 Mac mini 可运行 Docker Engine、Docker Compose 与临时 arm64 容器；
- 服务出现后，docker compose config 必须能通过，且每个有状态服务都有健康检查、restart policy 和备份/恢复说明；
- 重启 Mac、网络变化或 OrbStack 恢复后的常驻行为须在真实环境测试后才算通过，不能从安装成功推断；
- 外部 Satellite 只能连接 Gateway 的认证 LAN 端口，不能访问 Docker API 或数据库端口。

## 2. 开发机语音闭环

实现：

- 麦克风输入与扬声器输出；
- 本地唤醒词与 VAD 实验；开始可保留手动按键作为诊断路径；
- 腾讯云实时 ASR 的部分/最终转写、断开、超时和取消；
- 腾讯云实时 TTS 的文本分段、首音频播放、完成和取消；
- 文本深度推理适配器：只发送最终转写和最小化上下文，并探测模型、流式响应、超时与限流；
- 不在日志中打印音频、完整转录、API 密钥或完整记忆；
- 记录脱敏的延迟、错误码、音频秒数和 TTS 字符数；
- 明确设置腾讯云后付费状态、资源包/余额告警和本轮费用上限策略。

验收：

- 唤醒后能在本机完成一轮中文对话；
- 只有唤醒后的音频会到达 ASR；文本推理适配器从不收到音频；
- 用户说话可以中断正在播放的回答，并停止未完成的 TTS；
- 腾讯云或文本代理错误不会导致进程卡死、无限重试或持续录音；
- 关闭会话后本地状态可被明确观察；
- 可分别观察 ASR 首个/最终结果、文本首字节与 TTS 首音频延迟。

## 3. 会话与记忆服务

实现：

- sessions、messages、memory_items 与 memory_audit 的迁移模型；
- 记录短会话摘要；
- Memory Policy 输出 ADD / UPDATE / DELETE / NONE 的候选操作；
- 所有长期写入可复核、可单条删除、可按会话追溯；
- 向文本推理适配器仅传递策略允许的最小化摘要，不把完整会话或完整长期记忆作为默认上下文。

验收：

- 明确的“记住……”请求可写入；
- 临时闲聊默认不写入；
- 同一事实的新信息产生更新而非重复条目；
- 删除后检索与后续会话均不再看到该条内容；
- 审计记录能指出每段外发文本的最小化策略，而不保存原始音频。

## 4. 本地硬件与语音提供方评测

在同一房间测试至少三种情形：

- 安静环境下 2–3 米唤醒；
- 正在播放 Sol 的回答时发出打断指令；
- 旁边有人说话、电视/空调等持续噪声。

使用同一测试集比较标准实时 ASR 与大模型 2.0 ASR，并比较精品与大模型 TTS 音色。记录唤醒漏检、误唤醒、ASR 准确性、首句延迟、首音频延迟和打断成功率。硬件、ASR 档位和音色选择应以这些数据而非广告参数决定。

## 5. 只读家庭工具

先接入只读、可反复验证的能力，例如日历查询或 Home Assistant 的状态读取。工具调用须有调用记录、请求范围限制和失败回退。

联网搜索不在这一步默认接入；若将来引入，必须实现独立的 Search Provider，保存来源 URL、超时、费用和使用者可见的引用。

## 6. 后续能力

只有前四步稳定后，再分阶段评估：

- 独立的可引用 Search Provider；
- 多房间 Satellite；
- Home Assistant 写操作（明确确认与权限分级）；
- 面向其他入口的 MCP Memory Server；
- 多用户身份与隐私隔离。

## 需要你后续确认的选择

1. 第一个测试房间，以及可用的麦克风/扬声器；
2. 是否允许保留原始转录，以及默认保留多久；
3. 记忆写入是否允许自动执行，还是先显示待确认条目；
4. 腾讯云的后付费开关、单月预算和余额告警阈值；
5. Mac mini 的断电恢复、睡眠与登录恢复策略；
6. 将来需要接入的家庭系统（Home Assistant、日历、摄像头等）。
