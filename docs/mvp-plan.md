# 单房间 MVP 路线图

## 0. 先写清楚可验收的产品边界

首版用户：一个已授权的家庭成员。  
首版环境：一台开发机或一台房间设备。  
首版目标：本地唤醒后可连续说话、可打断、可查看和删除历史记录。

首版不承诺多人声纹识别、跨房间无缝转移、智能家居写操作或“任何话都永久记住”。

## 1. 开发机语音闭环

实现：

- 麦克风输入与扬声器输出；
- 本地唤醒词实验（开始可保留手动按键作为诊断路径）；
- Realtime 会话的建立、断开、超时和中断；
- 不在日志中打印音频、转录全文或 API 密钥。

验收：

- 唤醒后能在本机完成一轮中文对话；
- 用户说话可以中断正在播放的回答；
- 网络或 API 错误不会导致进程卡死或持续录音；
- 关闭会话后本地状态可被明确观察。

## 2. 会话与记忆服务

实现：

- sessions、messages、memory_items 与 memory_audit 的迁移模型；
- 记录短会话摘要；
- Memory Policy 输出 ADD / UPDATE / DELETE / NONE 的候选操作；
- 所有长期写入可复核、可单条删除、可按会话追溯。

验收：

- 明确的“记住……”请求可写入；
- 临时闲聊默认不写入；
- 同一事实的新信息产生更新而非重复条目；
- 删除后检索与后续会话均不再看到该条内容。

## 3. 本地硬件评测

在同一房间测试至少三种情形：

- 安静环境下 2–3 米唤醒；
- 正在播放 Sol 的回答时发出打断指令；
- 旁边有人说话、电视/空调等持续噪声。

记录每次的唤醒漏检、误唤醒、首句延迟和打断成功率。硬件与 wake word 选择应以这些数据而非广告参数决定。

## 4. 只读家庭工具

先接入只读、可反复验证的能力，例如天气、日历查询或 Home Assistant 的状态读取。工具调用须有调用记录、请求范围限制和失败回退。

## 5. 后续能力

只有前四步稳定后，再分阶段评估：

- 多房间 Satellite；
- Home Assistant 写操作（明确确认与权限分级）；
- 面向其他入口的 MCP Memory Server；
- 多用户身份与隐私隔离。

## 需要你后续确认的选择

1. 第一个测试房间，以及可用的开发机/小主机/麦克风/扬声器；
2. 是否允许保留原始转录，以及默认保留多久；
3. 记忆写入是否允许自动执行，还是先显示待确认条目；
4. 将来需要接入的家庭系统（Home Assistant、日历、摄像头等）。
