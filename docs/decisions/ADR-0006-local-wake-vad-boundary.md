# ADR-0006：VOICE-005 将本地唤醒与自动 VAD 保持在 Satellite 边界

## 状态

`accepted`

## 背景

[ADR-0005](ADR-0005-native-macos-voice-satellite.md) 已将首台 Voice Satellite 的权限、设备和实时音频放在原生 macOS 宿主机中，并把 VOICE-004 限制为显式手动激活的单轮闭环。VOICE-005 需要让用户在前台本地监听模式中通过唤醒词启动一轮对话，并以本地 VAD 自动结束输入。

这会扩大麦克风的本地使用时间、决定何时创建可计费的 ASR 会话，并在 Satellite、Gateway 与腾讯云之间增加新的状态与协议边界。若让 Gateway、Docker 容器或云端承担唤醒/VAD，就无法证明未唤醒音频没有离开设备，也会破坏现有的凭据隔离与 macOS 音频宿主决定。

## 决策

- VOICE-005 的首轮只在已由用户显式启动的前台本地监听模式中运行。Swift/AVFoundation Satellite 负责连续本地音频帧、唤醒检测、VAD 的语音开始/结束事件、物理/显式停止和本地状态；它继续不持有腾讯云、文本推理、数据库或 Docker 凭据。
- `LOCAL_LISTENING`、唤醒命中以及唤醒后尚未开始说话的等待阶段都只能在 Satellite 内存中处理。未唤醒音频、唤醒词音频、检测器缓冲和原始分数不得交付 Gateway、腾讯云、文本推理层、日志或磁盘；检测器的内存窗口必须有固定上限并在停止、设备变化和失败时清空。
- 只有本地 VAD 报告 `speech_started` 后，Gateway 才创建 VOICE-001 会话并向腾讯云 ASR 发送后续 PCM。无语音的误唤醒或唤醒后超时必须回到 `LOCAL_LISTENING`，且 ASR 调用数为零；唤醒前/唤醒词本身不作为 ASR 预滚音频发送。
- VAD 报告 `speech_ended` 后，输入按 VOICE-004 的有界时长、统一取消和安全关闭语义结束。首轮不允许因为连续静音、误唤醒或提供方失败而自动打开新的 ASR 会话或无限重试。
- 现有 SOL1 v1 手动采集协议不得被含糊复用。VOICE-005 必须通过显式能力协商或新版本帧来表达本地监听、唤醒、语音开始/结束和本地失败事件；未知能力或顺序错误必须在联网前安全失败。
- 唤醒引擎保持可替换、仅本地运行。实现先以 openWakeWord 为首个评测候选；若其误唤醒、漏唤醒、模型/运行时或资源要求不满足本规格验收，再带着同一房间样本评估 Porcupine。不得静默安装带遥测、联网推理或新的可计费账户依赖。
- AEC、降噪、语音驱动的播放打断、免手连续会话、后台/24 小时常驻、远场硬件选型和 LAN Satellite 不属于 VOICE-005 第一片；它们需要独立规格、房间实测和适用的 ADR。

## 后果

- Gateway 继续只处理已本地激活且已开始说话后的会话音频；原有腾讯云、文本推理、记忆和工具权限边界不变。
- Satellite 需要可注入的唤醒/VAD 引擎、时钟和音频帧源，才能用确定性假事件证明零云调用、VAD 结束、取消和缓冲清理，而不依赖真实麦克风或模型。
- 协议、Swift 宿主和 TypeScript 适配器都会改变，因而实现前必须有离线协议/状态机测试；真实模型下载、麦克风监听与云端单轮仍需分别取得用户授权。
- 首轮带来本地 CPU、内存和麦克风权限使用，但不增加云供应商或让未唤醒音频产生腾讯云费用。实际功耗、误唤醒率、漏唤醒率和房间声学效果不能从文档或模型宣传推断。
