# ADR-0002：首版采用腾讯云语音层与文本深度推理适配器

## 状态

已接受（2026-08-16）

## 背景

首版没有官方 OpenAI API 密钥，不能把 OpenAI Realtime API 作为语音闭环的前提。与此同时，家庭助手仍需要低延迟中文 ASR、可打断的 TTS，以及可替换的复杂文本推理能力。

将某个文本代理直接视为完整语音代理，会把音频、长期记忆、工具和供应商能力混在一起，也会错误假定其支持 Realtime、Responses API 或联网搜索。

## 决策

- Voice Gateway 使用腾讯云的实时 ASR 与实时 TTS；Satellite 只保留本地唤醒、VAD、采集/播放与静音控制。
- 腾讯云凭据只保存在 Gateway。未唤醒音频不离开设备；唤醒后的音频仅发送给 ASR，回答文本仅发送给 TTS。
- 复杂请求通过一个文本深度推理适配器处理。首个候选是本地 CLIProxyAPI，但它只被视为 OpenAI-compatible 的文本上游，不能被假定具备音频、联网搜索或任何特定模型能力。
- 每次部署前必须探测文本适配器的实际模型名、流式响应、超时和工具调用能力；不可用时应安全降级，而不是阻塞语音会话。
- MVP 不接入联网搜索。未来的搜索能力必须由独立 Search Provider 提供来源、超时、成本和审计边界。

## 后果

首版需要腾讯云账号与独立凭据，即使不使用官方 OpenAI API。腾讯云用量、文本代理配额和未来搜索费用应分别记录，不能混为“一个模型费用”。

Gateway 获得了稳定的供应商替换边界：腾讯云、文本代理和未来的 Search Provider 都可以分别评测或更换。代价是 Gateway 需要维护 ASR、TTS、文本流和打断取消的协调逻辑。

腾讯云实时语音的价格与免费额度会变动；代码不得写死价格，部署前应在控制台核验后付费开关、余额告警和资源包状态。
